## Goal of this prompt

Fix the P0 build reproducibility blocker: `include/OPT4001/Version.h` is included by public API but ignored/generated only in the PlatformIO flow. Clean manual and ESP-IDF builds must not fail because the header is missing.

The exploration report identified this as a high-severity issue:
- `include/OPT4001/OPT4001.h` includes `OPT4001/Version.h`.
- `.gitignore` ignores `include/OPT4001/Version.h`.
- `platformio.ini` generates it, but root CMake does not.
- Manual and ESP-IDF install claims are therefore not reproducible from a clean checkout.

## Implementation rules

Choose the cleanest robust approach. Acceptable patterns:

### Preferred option A — Commit deterministic `Version.h`

If `Version.h` content is deterministic from `library.json`, commit it and remove/adjust the ignore rule so it is tracked.

Also keep `scripts/generate_version.py check` as a guard that fails if the header is stale.

### Preferred option B — CMake/generic generation plus fallback

If you choose not to track `Version.h`, root CMake and a clean manual/native path must generate it before compilation. This must work for pure ESP-IDF and non-PlatformIO consumers. Avoid fragile implicit behavior.

### Not acceptable

- Rely only on PlatformIO pre-scripts.
- Leave `Version.h` ignored and missing from clean manual installs.
- Claim ESP-IDF component readiness without proving the header path.
